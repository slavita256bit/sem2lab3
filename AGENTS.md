  Основное хранилище освобождают деструкторы/clear. В main допускается delete
  временной копии при отмене изменения.
- Меню: 1 таблица класса, 2 добавление, 3 изменение, 0 выход. Новый объект сначала
  вводится, затем передаётся дереву через add(T*).
  При изменении tree[number] возвращает копию по значению. По копии найти оригинал
  через find и удалить remove(), затем изменить копию и передать её через add.
  При отмене удалить только временную копию; оригинал остаётся в дереве.
  Без свободных функций в main.cpp.
- print_read_info принимает istream, печатает подсказку через cout, сам читает >>
  и возвращает ссылку *this (ковариантно). Проверок состояния потоков не добавлять.
- Friend >>/<< непосредственно реализуют ввод/вывод, без read/write. Наследник
  вызывает оператор своей базовой части через static_cast, дописывает свои поля.
  *_TABLE_FORMAT только для своих полей, не склеивать макросы и не вводить WIDTH.
- print_header дополняет базовую шапку. Вывод дерева — friend operator<<,
  Vehicle::print_table удалён. Методов print/print_table у дерева нет. Номера 1..N
  внутри класса, в порядке ключа конкретного класса. [] использует те же номера
  и копирует объект, не меняя дерево. Для вывода не нужны typeid и dynamic_cast:
  известен конкретный T. dynamic_cast остаётся только при передаче временного
  Vehicle* из общего диалога в типизированное дерево.
- Короткие format в одну строку; цепочки << не переносить по длине. Подсказки
  нескольких строк — отдельными cout. Единицы таблиц в скобках, без |.
- VehicleField вместо магических номеров. Троллейбус: battery_capacity (кВт·ч).
- BinaryTree<T> объединяет дерево и узел без вложенного класса/предка. Поля value,
  left/right; пустое дерево value == nullptr. add(T*) и конструктор принимают владение
  выделенным объектом; не передавать адрес локальной переменной или один указатель
  повторно. clear удаляет и объекты, и поддеревья. Копирование дерева запрещено.
- Единственный remove() удаляет объект текущего узла. find один, возвращает узел
  (BinaryTree*) без константной перегрузки. find использует == всех полей; при равном
  ключе без полного совпадения продолжает поиск вправо. remove использует приватный
  extract(). [] не извлекает объект; неверный индекс вызывает std::out_of_range.
  В аргументах BinaryTree использовать object, не затенять поле value.
  При переносе из потомка сначала забрать value и связи через std::exchange,
  затем clear старых оболочек и установка сохранённых связей. Не обращаться
  к replacement после освобождения узлов. Пустые листья
  пропускать при обходе/поиске, использовать повторно при вставке.
- Порядок <, >, <=, >=: Vehicle по году, конечные классы по своим ключам:
  DumpTruck — body_volume, Bus — route, Trolleybus — battery_capacity. Дубликаты вправо.
  == и != сравнивают все собственные и унаследованные поля, включая String-марку.
  Явные инстанциации в cpp только DumpTruck/Bus/Trolleybus; отдельно инстанцируется
  свободный operator<<. Итераторы пока спроектированы, но не реализованы.
- Основные деревья существуют весь main; менять ключ через копию, find/remove,
  изменение и add.
  Индексы и счётчики — int вместо std::size_t; номера таблицы с 1.

### Файлы и стандартная библиотека
- Все `.h` текущей лабы хранить в `include/`, все `.cpp`, включая main, — в `src/`.
  Архив прошлой лабы не переносить и не переформатировать.
- Предпочитать готовые средства `std` собственным аналогам везде, где это не противоречит
  учебному заданию. Это прямое пожелание пользователя, а не только наблюдение по образцам.
- Длину C-строки в String получать через std::char_traits<char>::length, без ручного
  цикла и без strlen; это не заменяет собственное динамическое хранилище.
- Копирование/поиск/заполнение/сортировку выполнять через `<algorithm>`, когда есть
  подходящий алгоритм. Не писать свои циклы для уже готовой стандартной операции.
- Таблицу форматировать через `std::format` из C++20; собственные Table, print_cell,
  подсчёт UTF-8-байтов, дополнение пробелами и number_text не нужны.
  Поддержка кириллицы проверена на текущем компиляторе.
- `std::setw`/`std::left` допустимы, если подходят данным; для UTF-8 в узком потоке
  одно только setw не обеспечивает нужную ширину по символам.

### Пробелы и скобки
- UTF-8, LF, отступ ровно 4 пробела; табы в новых C++-файлах не использовать.
  Это нормализация под текущий проект: старые C/VS-лабы преимущественно с табами и CRLF.
- Allman: открывающая/закрывающая фигурная скобка на своей строке у функции,
  класса, if/else, switch и цикла. Исключение — короткие inline-конструкторы с `{}`.
- Для единственного простого оператора после if/for/while скобки не ставить;
  сам оператор писать следующей строкой с дополнительным отступом.
- После if, for, while, switch — один пробел до `(`. У вызова функции пробела нет:
  `if (condition)`, `for (int i = 0; i < n; i++)`, `object.read(stream)`.
- Внутри круглых и квадратных скобок пробелы не ставить: `a[i]`, `(a + b)`.
  После запятой и после `;` в заголовке for — один пробел; перед ними пробела нет.
- Вокруг бинарных операторов и присваивания — один пробел: `a + b`, `x = value`,
  `stream << value`, `pointer != nullptr`, `condition ? a : b`.
- Унарные операторы, `->`, `::`, `.`, `[]` прилегают к операнду. В обычных циклах
  использовать привычное по образцам `i++`; формы ++/-- строки сохранять по заданию.
- В объявлении тип указателя/ссылки писать слитно с типом: `String& value`,
  `const String& other`, `Vehicle* object`, `Vehicle** objects`.
  Старое `char *name` встречается в C, но не является правилом новых C++-файлов.
- Инициализировать поля в объявлении: `int year = 0;`, `char* data = nullptr;`.
  Числовые локальные переменные перед прямым вводом инициализировать через `= 0`;
  для буфера символов использовать `{}`, чтобы он изначально был пустым.
- Список инициализации короткого конструктора — на строке сигнатуры, если помещается;
  длинного — следующей строкой с отступом 8 пробелов: `: Base(...), field(field)`.

### Пустые строки и переносы
- `#pragma once` — первая строка заголовка. Подключения — подряд, без пустых строк
  между каждым include; после блока подключений — одна пустая строка.
- В .cpp сначала подключать свой заголовок, затем остальные нужные заголовки.
  Порядок системных и локальных include в старых работах неодинаков: общего
  требования сортировать их по алфавиту нет.
- Между отдельными определениями функций — одна пустая строка.
  Комментарий-название прилегает к сигнатуре, сигнатура — к открывающей скобке.
- После `{` и перед `}` не оставлять пустые строки. Перед отдельным завершающим
  return — одна пустая строка, если выше выполнен содержательный блок действий;
  короткому геттеру пустые строки не нужны.
- Внутри функции отделять одной пустой строкой логические этапы: подготовку данных,
  ввод, вычисление, вывод/возврат. Связанную пару «подсказка → ввод» не разрывать.
- В .h поля, private-вспомогательные методы и public-методы разделять пустой строкой.
  Конструкторы, геттеры/сеттеры, ввод/вывод и friend-операторы группировать отдельно;
  пару get_X/set_X держать рядом. Между многострочными inline-определениями — пустая строка.
- case располагать на уровне switch; тело case — ещё на 4 пробела правее.
  Разные case разделять одной пустой строкой. Если case требует локальную область,
  его скобки находятся под case. Хвост do/while писать с `while (...)` на новой строке.
- Длинные вызовы/форматные строки переносить по группам аргументов; продолжение
  с отступом ещё 4 пробела. Это правило относится к вызовам функций.
  Цепочки << не переносить из-за длины строки; многострочный текст подсказок
  выводить отдельными std::cout для каждой строки, без склейки соседних литералов.
  Не переносить каждый короткий аргумент на отдельную строку без причины.
- Пробелы в конце строк и пробелы на пустых строках удалять. В конце файла — ровно LF.

### Имена, комментарии и учебная логика
- Классы — PascalCase; поля, параметры, методы и свободные функции — snake_case;
  существующие MAX_LENGTH и аналогичные макросы — UPPER_SNAKE_CASE.
- В C сохранять принятые префиксы структуры (tree_, queue_, stack_); в C++ методы
  принадлежат классу и не требуют такого префикса. Внутри методов поля — через this->.
- Комментарии на русском, короткие, с названием действия: «Получение …»,
  «Изменение …», «Ввод …», «Вывод …». Не расписывать очевидные строки внутри функций.
- По прямому требованию пользователя/преподавателя все правые комментарии `//`
  в заголовках текущей лабы начинаются в одной колонке — 101-й (100 символов перед //).
  Выравнивать пробелами, а не табами; не делать отдельную колонку для каждого класса.
- В .cpp комментарий-название стоит над функцией, с нулевым отступом (колонка 1).
  Это отдельный вид комментария, он не переносится в 101-ю колонку. Блок задания
  и блок тестового ввода также начинаются у левого края.
- У новых полей и объявлений методов в заголовках должны быть короткие правые
  комментарии; все перегрузки одной операции можно подписывать одинаково.
- const-методы для чтения, параметры-объекты через const&, private-поля перед public.
  Конструкторы/деструкторы по требованию преподавателя остаются в заголовках.
- Сохранять ранний return для простых особых случаев; не наращивать вложенность.
  Результат операции по возможности сразу выводить через поток без лишних переменных.
- По последнему требованию преподавателя ввод реализовать прямо в operator>>,
  без object.read(stream) и отдельных методов read. Унаследованные поля читать
  через >> базовой части с static_cast<Base&>(object). Форматирование общего вывода
  находится прямо в operator<<, без object.write(stream). Оба оператора возвращают
  тот же поток; подсказки ввода остаются в main.
- В конце main — `return 0;`. Примеры тестового ввода — блочным комментарием после main.
- Старые закомментированные варианты в архиве допустимы; новый код не засорять ими.

  остаётся динамическим char*, без C-функций строк и без std::string внутри String.
  При переносе исправлять ошибки памяти; исходную папку прошлой лабы сохранять.
- Данные программы — в памяти, файловый ввод/вывод пока не использовать.
- По последнему прямому пожеланию пользователя коллекция транспорта — std::vector<Vehicle*>,

- write и print_header принимают common_table = true. В режиме false выводят только
  унаследованные и собственные поля своего класса, без пустых посторонних столбцов.
  operator<< сохраняет общий формат; virtual write используется таблицами и в общем
  режиме вызывает << для своего типа. Для границ выбора использовать objects.size().
- В main пункт 8 после выбора объекта выводит таблицу его класса. Не добавлять отдельный

- rewind(stdin) оставлен ниже как историческое пожелание для Windows. В новой Linux-лабе

- Ввод выполнять напрямую, без любых проверок состояния или результата cin/stream.
  Не добавлять if (cin), if (stream), if (!(cin >> ...)), fail()/eof() и их аналоги.

## Повтор программы
- В main внешний while (true): создание и ввод объектов → таблица и изменение полей →
  вопрос «Завершить программу? (y/n):». Выход по y/Y через std::tolower;
  передавать символ в tolower через static_cast<unsigned char>.
- 0 в выборе объекта завершает только изменение полей, затем задаётся вопрос о выходе.
- Объекты локальны для одной итерации внешнего цикла: уничтожаются перед следующей
  итерацией или выходом, данные для нового прохода вводятся заново. Новые слои/функции
  управления диалогом и проверки состояния потока не добавлять.

## Первоначальный ввод и номера строк
- Единицы измерения в шапке консольной таблицы писать в скобках, а не через запятую:
  «Груз (т)», «Кузов (м3)», «Сеть (В)».
- Подсказки первоначального ввода писать в формате «Название (поле, поле, ...)»;
  единицы измерения указывать рядом с полем: грузоподъёмность(т), объём кузова(м3).
- По последнему пожеланию пользователя активный вариант main создаёт транспорт
  конструкторами с параметрами и готовыми значениями. Предыдущие объявления без
  параметров и первоначальный ввод через >> сохранены одним закомментированным блоком,
  чтобы можно было переключиться обратно. Диалог изменения полей остаётся активным.
- Марка — одно слово без пробелов. Все поля объекта вводятся одной строкой, например
  `Belaz 2024 40 25`: марка, затем числа в порядке базовый → производный класс.
  Подсказку завершать `: ` без перевода строки, чтобы вводить сразу после неё.
- В String::operator>> читать через `stream >> buffer` (массив char известного размера,
  C++20 ограничивает число извлекаемых символов размером массива). getline не использовать;
  отдельный std::ws перед чтением марки не нужен.
- Первым столбцом общей таблицы выводить №, начиная с 1. Номер строки совпадает
  с номером объекта для изменения. Номер вычисляется при выводе и не хранится в объекте.

## Реализация вывода в операторах
- Форматирование общей строки каждого класса находится прямо в его operator<<.

### Лаба 2 — перегрузка операций
Класс `String` для работы со строками символов (без вариантов, одно условие на всех):
- конструктор без параметров, конструктор с параметром-строкой (не длиной), конструктор копирования, оператор `=`.
- `+` конкатенация — `friend`, **3 перегрузки**: `String+String`, `String+const char*`, `const char*+String`
  (конструктор от `const char*` — `explicit`, поэтому на каждую комбинацию нужна своя перегрузка, implicit-конверсии нет).
- `-` вычитание строк — метод класса.
- `+=` — метод класса.
- `++` (приведение к верхнему регистру) и `--` (к нижнему регистру) — методы класса.
- `<`, `>`, `<=`, `>=` — через `strcmp`, возвращают `bool`, `friend`.
- `[]` — метод класса.
- `()(int, int)` — выделение подстроки, метод класса.
- `<<`, `>>` — ввод/вывод, `friend`.
- `operator new` / `operator delete` — методы класса.
- Реализация: `sem2lab2/sem2lab2/String.h` + `String.cpp`, демонстрация всех операций в `sem2lab2.cpp` (в т.ч. пример `"БГУИР" + a + b + c + "ФКСИС"` из условия).
- Явное пожелание пользователя: внутри `String` не использовать C-функции работы со строками (`strcpy_s`, `strcat_s`, `strcmp`, `strlen`, `_strupr_s`...) и не использовать `std::string` как реализацию. Хранилище — свой `char*` (динамическая память), а операции над ним — через `<algorithm>`/`<locale>`: `std::copy`/`std::copy_n`/`std::fill_n` вместо копирования, `std::search` для поиска вхождений подстроки (используется в `operator-`), `std::toupper(char, locale)`/`std::tolower(char, locale)` в обычном `for`-цикле (без лямбд/`std::transform`) для регистра, `std::lexicographical_compare` для `<`/`>`/`<=`/`>=`. `operator new`/`delete` класса — через `::operator new`/`::operator delete`, не `malloc`/`free`.
- Приватный метод выделения памяти называется `allocate` (не `assign`) и **не** освобождает старые данные — вызывающая сторона (`operator=`, `read`) сама делает `delete[]` перед вызовом `allocate`. Только одна перегрузка: `allocate(const char* str)` (конструктор `String(int count, char fill)` и вторая перегрузка `allocate` были добавлены и затем убраны по просьбе пользователя — не возвращать).
- В комментариях "Получить X" заменено на "Получение X" (методы-геттеры, `[]`, `()`).
- `read(std::istream& stream, bool until_ln)` — `bool`-параметр выбирает разделитель чтения (`until_ln ? '\n' : ' '`), по аналогии с `read_string(s, until_ln, max_len)` из лаб по C. Ограничение длины ввода — `#define MAX_LENGTH 80` в `String.h`; при переполнении `stream.getline` ставит failbit, `read` печатает ошибку и просит ввести заново (цикл `while(true)` + `stream.clear()` + `stream.ignore(...)`), как `read_number`/`read_string` в старых C-лабах.
- `main` — не свободный ввод в цикле, а меню с однобуквенными командами и `switch` в `do { ... } while (action != 'x')`, по образцу `binary_tree.cpp`/`struct_lab.cpp` (печать списка команд каждую итерацию, `std::cin >> action`, затем пропуск остатка строки перед чтением строк через `getline`, чтобы не ловить пустую строку от предыдущего символа).
- Пользователь просил объединять операции в выражения, чтобы не разводить лишние `case`: вместо отдельных случаев на каждый оператор — один `case` на логическую группу, а результат оператора пишется прямо в `std::cout << (...)` без промежуточной переменной (где оператор это позволяет, например `a += b` возвращает `*this`, поэтому `std::cout << (a += b)` одновременно и меняет, и печатает). В меню сейчас: `o` — конкатенация/вычитание/`+=`, `r` — `++`/`--`, `e` — `[]`/`()`, вместо прежних `c`/`s`/`d`/`u`/`l`/`i`/`t`.
- Без `std::numeric_limits`, и затем без ручного `while`-пропуска вовсе: пропуск остатка строки — через `rewind(stdin)` (`<cstdio>`), как в лабах по C (`my.cpp`: `if (flush_buffer) rewind(stdin);`). Это осознанное исключение из правила "без C-функций" — применяется только к сбросу консольного ввода в `operator>>` и в `main`, не к внутренней логике `String`.
- `allocate(int new_length)` выделяет память и больше ничего не делает. Конструкторы и деструктор живут в `String.h` (так просит преподаватель): `String() : String("") {}`; `String(const char*)` считает длину, вызывает `allocate` и копирует через `std::copy`; `String(const String&) : String(copy.data) {}`. `operator=` без `std::swap`: `delete[] data; allocate(other.length); std::copy(...)`. `operator>>` при успешном чтении делает `s = String(buffer);`.
- Пользователь и преподаватель хотят максимально чистый код. Никаких поясняющих комментариев внутри функций и «умных» пометок вроде «как в лабах по C» или «copy-and-swap». Допустим только короткий комментарий-название над функцией или справа от объявления («Получение …», «Сложение строк»).
- `operator-` сокращён: ранняя проверка `if (other.length == 0) return String(this->data);` в начале вместо тройного оператора внутри цикла, убраны лишние алиасы (`text_begin`/`pattern_begin` — это просто `this->data`/`other.data`), цикл `while(true) { ... if (match==end) break; }` заменён на `do { ... } while (match != text_end);`.
- `++`/`--` — есть и префиксная, и постфиксная форма (`operator++(int)`/`operator--(int)` с фиктивным `int`-параметром по стандартной договорённости C++); постфиксная реализована через префиксную: копия `*this`, затем `++(*this)`/`--(*this)`, возвращается старое значение.
- Методов `read`, `write`, `c_str` и `get_length` нет: неиспользуемое удаляем. Ввод и вывод только через `friend operator>>` и `operator<<`, причём `operator<<` выводит `s.data` напрямую.
- Внутри `String` (включая `operator>>`, `operator new`/`operator delete`) не печатаем диагностические `std::cout` — весь информативный вывод снаружи, в `sem2lab2.cpp`. `operator>>` при превышении `MAX_LENGTH` просто оставляет `stream` в состоянии ошибки (как стандартные `operator>>` для `std::string`/чисел) и не трогает `s`, если чтение не удалось; цикл повторного запроса с сообщением и `rewind(stdin)` теперь живёт в свободной функции `read_string(stream, s)` в `sem2lab2.cpp`, которую использует `case 'a'`.
- `operator new`/`operator delete` — просто `return ::operator new(size);` / `::operator delete(ptr);`, без логирования. Напрямую `new`/`delete` тут писать нельзя: `ptr` в `operator delete` — это `void*` (нет типа для вызова деструктора), а `new`/`delete`-выражения внутри самих перегрузок `String::operator new/delete` рекурсивны/не то действие; `::operator new`/`::operator delete` — это и есть "просто выделить/просто освободить" без конструктора/деструктора.
- Конструктор без параметров теперь явно демонстрируется отдельной переменной в `case 'n'` (`String empty;`), а не только неявно через `String a, b;` в начале `main`.
- `main`: ввод A и B объединён в один пункт меню (`a`), пункта `p` для вывода больше нет — `A`/`B` печатаются после каждого действия автоматически (в конце цикла `do`). `operator=` явно демонстрируется в `case 'o'` вместе с остальными операциями (`B = A -> ` как часть цепочки выражений).
- `++`/`--` переопределены: это не "верхний/нижний регистр" (как в исходном условии лабы), а инкремент/декремент последнего символа строки с переносом ('z'→'a' и перенос на предыдущий символ для `++`, 'a'→'z' аналогично для `--`), перенос останавливается на первом символе без переполнения массива (строка "zzz" при `++` становится "aaa", а не растягивается). Это осознанное отступление от текста условия по прямой просьбе пользователя — если преподаватель спросит, у `String` всё ещё остаются все требуемые операторы, просто с другой семантикой `++`/`--`.
