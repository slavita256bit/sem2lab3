## Иерархия и поля

| Класс | База | Собственные поля | Статус |
| --- | --- | --- | --- |
| Vehicle | — | String brand, int year | Абстрактный |
| CargoVehicle | Vehicle | double payload, т | Абстрактный |
| DumpTruck | CargoVehicle | double body_volume, м3 | Конечный |
| PassengerVehicle | Vehicle | int seats | Абстрактный |
| Bus | virtual public PassengerVehicle | int route | Конечный |
| Trolleybus | virtual public PassengerVehicle | double battery_capacity, кВт·ч | Конечный |

Три уровня, всего шесть предметных классов. Верхние три абстрактны через чистый
виртуальный print_read_info(std::istream&). В main создаются только конечные классы.
Виртуальную PassengerVehicle инициализирует самый производный конструктор Bus или
Trolleybus. У всех предметных классов есть обычный, параметрический и копирующий
конструкторы, деструкторы с диагностикой, геттеры/сеттеры и friend >>/<<.

## Владение и меню

- Три постоянных типизированных дерева: BinaryTree<DumpTruck> dump_trucks,
  BinaryTree<Bus> buses, BinaryTree<Trolleybus> trolleybuses. Общего массива,
  count и MAX_VEHICLE_LENGTH нет. Хранилище не ограничено 25 элементами.
- Узел владеет value (T*) и обоими поддеревьями. Конструктор от T* и add(T*)
  принимают владение: передавать выделенный через new объект, не адрес локального
  объекта и не один указатель дважды. add(nullptr) ничего не делает.
- Деструктор вызывает clear(): удаляются поддеревья и их объекты, затем свой value.
  Ручного обхода с delete в main нет. remove() удаляет объект выбранного узла.
- tree[number] возвращает независимую копию T по значению; дерево не изменяется.
  Индексы и счётчики int, номера с 1. Неверный номер (включая отрицательные и 0)
  вызывает std::out_of_range. main ловит его и сообщает о неверном номере.
- ADD_DEFAULTS включает по два объекта каждого конечного класса. Без определения
  макроса деревья изначально пустые; добавление остаётся доступно.
- Меню: 1 таблица класса, 2 добавление, 3 изменение, 0 выход. Классы: 1 DumpTruck, 2 Bus, 3 Trolleybus; 0 отмена.
- Новый объект сначала создаётся и читается через виртуальный print_read_info(cin),
  затем передаётся соответствующему дереву. Дерево не должно индексировать объект
  до завершения ввода его полей. Короткие switch остаются в main; функций вне main нет.
- При изменении создаётся new T(tree[number]). Если поле отменено, удаляется
  только эта копия. Иначе find(copy)->remove() удаляет оригинал до изменения копии,
  затем change_field и add передают изменённую копию дереву. Сортировка сохраняется.
  main может удалять временную копию при отмене; основные объекты удаляет дерево.
- Во время общего диалога main использует временный Vehicle*. Возврат в конкретное
  дерево — через прямой dynamic_cast соответствующего типа, установленного выбором
  класса. Для Bus/Trolleybus обычное обратное static_cast невозможно из-за
  виртуальной базы. Смешанной коллекции Vehicle* и RTTI-выбора строк больше нет.
- VehicleField: Brand=1, Year, Payload, BodyVolume, Seats, Route, BatteryCapacity.
  Меню печатает номера через static_cast<int>, введённый номер приводится один раз.
  Неизвестные поля наследник передаёт базовому change_field.
- Удаление через отдельный пункт меню пока не добавлено: доступно API node->remove().

## Потоки и таблицы

Операторы потоков невиртуальные. Наследник вызывает оператор базовой части через
static_cast и дописывает только свои поля. То же правило для шапок. Каждый
*_TABLE_FORMAT содержит собственные столбцы, форматы не склеивать и не вводить WIDTH.

Вывод дерева — только через friend operator<<, старого Vehicle::print_table нет. Он выводит
шапку через print_header объекта своего класса и строки через соответствующий <<.
Тип T известен при компиляции: typeid-фильтр и dynamic_cast для вывода не нужны.
Номера 1..N относятся к симметричному обходу выбранного дерева, совпадают с []
и пересчитываются после изменения состава или порядка. Общей таблицы нет.
String поддерживает std::formatter, марку не переводить через ostringstream.

## Дерево и сравнения

BinaryTree объединяет дерево и узел; вложенного класса и предка нет. Поля value,
left/right; value == nullptr означает пустой узел без непустых потомков.
Конструкторы/деструктор в h, остальные методы в cpp. Явные инстанциации теперь
только DumpTruck, Bus, Trolleybus. Новый T требует инстанциации класса и отдельного
operator<<: явная инстанциация класса не создаёт свободный оператор.
Оператор вывода требует от T print_header и <<; для не-транспортных типов этот интерфейс
придётся отдельно согласовать. Копирование дерева запрещено.

Операторы порядка <, >, <=, >= используют год в Vehicle, body_volume в DumpTruck,
route в Bus, battery_capacity в Trolleybus. == и != сравнивают все поля, включая
базовые: Vehicle — марку/год, CargoVehicle дополнительно payload,
PassengerVehicle seats, конечный класс своё поле. String == сравнивает длину
и символы через std::equal. Равенство ключей не обязательно означает == объектов;
для одного ключа <= и >= могут быть true при == false. Это разные отношения.

find один: возвращает BinaryTree* объекта с полным совпадением либо nullptr.
Если ключ равен, но == false, поиск продолжается вправо; так можно найти нужный
объект среди одинаковых ключей. Полностью одинаковые записи неразличимы по ==,
удаляется первая совпавшая, состав значений после замены остаётся правильным.
Удаление найденного элемента:

```cpp
if (auto* node = tree.find(key))
    node->remove();
```

Единственный remove() без аргументов удаляет объект текущего узла, false — узел пуст.
Для общей механики используется приватный extract(): он отсоединяет объект без
уничтожения и возвращает его указатель. remove удаляет этот объект. extract остаётся приватной частью удаления,
а [] только копирует выбранный объект. При двух потомках extract берёт объект минимального узла
справа, рекурсивно извлекая его. При одном — переносит value и связи потомка.
У освобождаемого потомка обнуляются и value, и обе связи: иначе новый владеющий
деструктор уничтожил бы перенесённые данные. Объекты не копируются и не срезаются.

Пустой лист остаётся выделенным. Поиск/обход пропускают его, add использует повторно;
пустые непосредственные потомки очищаются при extract родителя или общем clear.
Сохранённые узлы и итераторы нельзя использовать после изменения дерева.
Итераторы пока только спроектированы: внешний класс со стеком пути, см. LAB4.md.


Нельзя менять ключ через сохранённый указатель, пока объект находится в дереве.
Основной диалог использует копию, find/remove, изменение и add. При просмотре
дерево не перестраивается.
Типизированные деревья уже используют разные ключи конечных классов.

Последнее уточнение: [] возвращает копию T, номера/счётчики int. Проверено, что
чтение [] и изменение копии не меняют дерево; неверные индексы вызывают исключение.
find использует полное ==, включая марку/год и поля промежуточных классов; проверены
одинаковые ключи с отличием только payload или seats. main удаляет оригинал до
изменения копии, при отмене оригинал не трогает. Проверены GCC/Clang, ASan/UBSan
(без LeakSanitizer), 300 случайных замен записей, все случаи удаления и пустые узлы.
В extract добавлен явный if (replacement) перед чтением полей потомка.

Уточнение предупреждений: аргументы конструктора/add/find BinaryTree называются
object, поле value не затеняется. extract сначала забирает собственный value через
std::exchange, проверяет наличие непустых поддеревьев. При одном/нуле потомков
сохраняет next_value/next_left/next_right, обнуляя поля replacement через exchange;
только после всех чтений вызывает clear и устанавливает сохранённые указатели.
До чтения replacement нет удаления пустых потомков. Ветка двух потомков по-прежнему
рекурсивно извлекает минимальный объект справа. Внешнее поведение сохранено.
