# Лабораторная работа 6 — текстовые и бинарные файлы

Подготовка в ветке `lab6` от версии лабы 5. Требования сверены с записью
задания и фотографией схемы с доски.

## Требования преподавателя

1. Сохранить предыдущие лабораторные. Изменения для лабы 6 вести отдельно.
2. Сохранять все данные из шаблонных контейнеров лабы 4 в двух форматах,
   текстовом и бинарном. Сохранение можно выполнять во время работы или при выходе.
3. При запуске загружать данные из выбранного текстового или бинарного файла и
   восстанавливать объекты в контейнерах.
4. Перегрузить операторы ввода и вывода для сохраняемых объектов.
5. Реализовать отдельные шаблонные классы для текстового и бинарного файлов.
   Поддержать другие типы данных через операции ввода и вывода для этих типов.
6. Для проверки сохраниться, завершить программу и при следующем запуске прочитать
   полученный файл. Повторить проверку для обоих форматов.

## Файловые классы

На доске общий базовый класс `File` и два шаблонных наследника. Имена в схеме
приведены как на доске.

```text
         File
        /    \
File_txt<T>  File_bin<T>
```

`File` общий для работы с путём и файловым потоком. `File_txt<T>` читает и
записывает текстовые записи типа `T`, `File_bin<T>` — бинарные. Для нового `T`
добавляются операции для этого типа. Сами файловые шаблоны работают через эти
операции и не зависят от набора полей транспорта.

`operator<<` транспорта должен быть универсальным. Для текстового представления
предлагается перегрузка с `std::ostream&`, которая одинаково пишет в консоль,
файл или строковый поток и сохраняет все поля. Соответствующий `operator>>`
читает ту же запись. Форматирование строк таблицы и подсказки для ручного ввода
в этом варианте остаются отдельными операциями. Интерфейс бинарных операций
ещё предстоит выбрать.

## Данные проекта

Один файл содержит снимок всех трёх деревьев. При загрузке каждую запись
помещаем в `BinaryTree<T>` соответствующего типа. Сохраняем все поля, включая
унаследованные, и все записи с одинаковыми ключами, в том числе полные дубликаты.
Пустое дерево тоже должно восстанавливаться пустым.

| Дерево | Поля записи по порядку |
| --- | --- |
| `BinaryTree<DumpTruck>` | Марка, год, грузоподъёмность, объём кузова |
| `BinaryTree<Bus>` | Марка, год, число мест, маршрут |
| `BinaryTree<Trolleybus>` | Марка, год, число мест, ёмкость аккумулятора |

Содержимое можно получить обходом `iterate(tree)`. Достаточно восстановить
состав деревьев и порядок записей для таблиц. Для `String` сохраняем символы
марки, для транспорта — значения его полей. В текстовом файле дробные значения
записываем с точностью, достаточной для чтения обратно в тот же `double`.

## Согласованный диалог

- При запуске выбрать источник данных — клавиатура, текстовый файл или бинарный
  файл. После успешной загрузки открыть обычное меню с восстановленными деревьями.
- При выходе выбрать текстовое сохранение, бинарное сохранение или выход без
  сохранения. Доступны оба формата, а за один выход пользователь выбирает один.
- При загрузке и сохранении показать путь по умолчанию для выбранного формата и
  дать ввести другой путь или имя файла. Пустой ввод подтверждает показанный
  путь. Оба пути по умолчанию задать в одном месте в коде для простой замены.

Предлагаемое поведение при ошибках:

- При ошибке загрузки показать причину и снова предложить выбор источника.
  Загружать снимок целиком, чтобы повреждённый файл не заполнял деревья частично.
- При ошибке сохранения показать причину и дать повторить попытку или вернуться
  в меню с текущими данными.

Для режима с клавиатурой предлагается начать с пустых деревьев и вводить объекты
через существующий пункт добавления. Возможность оставить демонстрационные
записи `ADD_DEFAULTS` нужно согласовать отдельно.

## Предлагаемое устройство файлов

- Порядок секций фиксирован — самосвалы, автобусы, троллейбусы. Каждая секция
  начинается с количества записей, после которого идут сами записи. Нулевое
  количество обозначает пустое дерево.
- Текстовый файл содержит читаемые значения полей. Для марки и остальных полей
  согласуем разделители. Текстовая запись должна читаться обратно целиком.
- Бинарный файл содержит числовые значения и длину марки с её байтами. Согласуем
  размеры числовых полей и нужна ли совместимость между платформами. Объекты
  восстанавливаются из полей через обычные операции создания и вставки.
- Проверки полей переиспользуют правила лабы 5. Ошибки открытия, чтения и записи
  можно оформить через отложенный `FileError`. При обрыве записи загрузка
  должна закончиться сообщением об ошибке.

## Открытые вопросы

1. Универсальные `<<` и `>>` должны обслуживать оба формата или достаточно
   общих потоковых операторов для текста и отдельных операций для бинарных полей?
2. Что означает ввод с клавиатуры при старте — пустые деревья и обычное меню
   добавления, демонстрационные записи или отдельный начальный ввод?
