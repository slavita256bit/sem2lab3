# Лабораторная работа 4 — шаблоны и бинарное дерево

## Условие

Включить предыдущую лабораторную по наследованию с изменениями в отдельный проект
лабы 4 (или предварительно согласованную отдельную ветку). Шаблоны используются
до конца семестра и далее в курсовой. Контейнер хранит объекты классов лабы 3.

Варианты: стек с поиском/удалением произвольного элемента; двунаправленная очередь;
двунаправленный список; кольцо; бинарное дерево. Выбран вариант «бинарное дерево».
Требуются шаблон контейнера и шаблонное представление его элементов, добавление,
удаление выбранного элемента, поиск, вывод на экран, зацикливание программы.
Для будущей высокой оценки предполагается разделение на контейнер, итератор
и алгоритмы; это следующий этап, не требование к нынешнему каркасу.

По последней просьбе пользователя узел и дерево — один класс BinaryTree<T>,
без вложенного Node и отдельного TreeNode. Каждый экземпляр хранит T* value
и связи BinaryTree* left/right; пустой корень имеет value == nullptr.
Теперь дерево владеет и объектом T, и поддеревьями; объекты каждого конечного
класса находятся в своём постоянном типизированном дереве вместо общего массива.

Пример icpc_qual2026/1.cpp показывает рекурсию и работу с указателями/ссылками,
но является другим видом дерева: спортивные сокращения и алгоритм не копировать.

Текущий интерфейс удаления — только remove() без аргументов у выбранного узла.
Предка хранить не нужно, delete this не используется. Сначала find(object) ищет по == всех полей и возвращает узел,
затем вызывается node->remove(). Перегрузка find теперь одна, для изменяемого дерева.
Константный поиск пока не предусмотрен.

Лист становится пустым: value = nullptr, но его оболочка остаётся связанной
с родителем. Это допустимый пустой узел. Обход и поиск его пропускают, add использует
повторно. Пустой узел никогда не содержит непустых поддеревьев. При следующем
удалении из родителя его пустые непосредственные потомки освобождаются.

При одном непустом потомке текущий узел принимает его T* и связи; перенесённые
связи сначала обнуляются в освобождаемой оболочке. При двух потомках берётся T*
минимального непустого узла справа и вызывается приватный extract() этого узла. Он либо
становится пустым, либо принимает своё правое поддерево. Поиск минимума должен
пропускать пустого левого потомка. Текущий экземпляр остаётся на месте.
Перемещение между узлами не копирует объекты. remove() уничтожает извлечённый
объект, а tree[number] возвращает независимую копию T, не извлекая оригинал. Приватный extract() используется только внутри удаления; публичная перегрузка remove остаётся одна.
Перед освобождением оболочек value и связи потомка забираются через
std::exchange в локальные указатели. Затем вызывается clear старых оболочек,
и сохранённые указатели устанавливаются в текущий узел. К replacement после
освобождения памяти обращений нет.

## Сравнения и деревья конечных классов

Порядок <, >, <=, >= задаётся ключом: Vehicle — год, DumpTruck — объём кузова,
Bus — маршрут, Trolleybus — ёмкость аккумулятора. Операторы ==/!= сравнивают
все поля (включая базовые). String дополнен сравнением содержимого через std::equal.
Равный ключ не гарантирует ==; одинаковый порядок и полное равенство — разные вещи.

Дубликаты ключей по-прежнему вставляются вправо. find сначала проверяет полное ==,
иначе идёт влево для меньшего ключа или вправо для большего/равного. Так находится
запись с нужными полями даже за другими записями с тем же ключом. Если все поля
совпадают, записи по значению неразличимы; для удаления достаточно любой из них.
Типизированный контейнер использует сравнения своего T, без RTTI для порядка.

Здесь шаблон реализован в cpp с явными инстанциациями для DumpTruck, Bus
и Trolleybus. Эти три специализации доступны из других файлов. Оператор вывода
использует print_header и << транспорта, поэтому для произвольного типа
его интерфейс потребует отдельного решения. Для нового
типа требуется добавить include, template class BinaryTree<NewType> и явную
инстанциацию свободного operator<< в cpp;
одного объявления в h недостаточно. Если понадобится произвольный тип из внешнего
кода, отдельно согласовать перенос определений в подключаемый файл шаблона.

Нельзя менять ключ непосредственно в дереве. main получает копию через [],
до изменения находит оригинал по этой копии и удаляет find(copy)->remove(),
затем меняет копию и добавляет её как новый объект. При отмене оригинал остаётся
в дереве, удаляется только временная копия. Удалять по старому полному значению
после изменения копии нельзя: == уже не совпадёт.

## Как будут выглядеть итераторы без предка

План, не реализованный интерфейс: внешний класс BinaryTreeIterator<T> хранит
стек пути std::vector<const BinaryTree<T>*>. Сам BinaryTree не содержит предка.
Для доступа внешнего итератора к закрытым value/left/right понадобится friend.
Вложенный класс для этого не нужен. Вектор относится только к пути обхода,
не заменяет согласованное хранилище транспорта.

begin() спускается от корня влево, помещая каждый непустой узел в стек.
Верхушка — текущий элемент. operator* возвращает const T&, operator-> — const T*.
Изначально лучше давать только константный доступ: изменение ключевого поля через итератор
нарушит порядок дерева. Константный итератор не запрещает изменять объект через
другие ранее сохранённые ссылки — этим должен управлять вызывающий код.

operator++ снимает текущую вершину со стека. Если у неё есть непустое правое
поддерево, добавляет в стек путь к его самому левому непустому узлу. Если правого
поддерева нет, верхушка оставшегося стека уже является следующим предком для вывода.
Пустые узлы не добавляются. end() соответствует пустому стеку.

Пример будущего использования (сейчас begin/end и Iterator ещё не написаны):

```cpp
for (auto iterator = tree.begin(); iterator != tree.end(); ++iterator)
    std::cout << *iterator << '\n';
```

Нужно также определить ==/!= (учитывать дерево и текущий узел), копирование
итератора с независимой копией стека и iterator_traits перед использованием
стандартных алгоритмов. Начальный вариант — прямой обход, без operator--.
Память итератора O(h), begin O(h), один ++ в худшем O(h), полный обход O(m),
где m включает пустые выделенные узлы. При большом числе пустых листьев число
посещённых оболочек может отличаться от числа выданных объектов.

Первоначальное правило: add/remove/clear инвалидируют все итераторы. remove()
может менять объект в сохранённом узле и физически освобождать оболочку потомка;
стек пути после этого нельзя продолжать использовать. Для удаления во время
обхода позже потребуется отдельный согласованный erase(iterator) с восстановлением
позиции. До его реализации итератор после изменения дерева нужно получать заново.

## Семантика []

T operator[](int number) возвращает независимую копию по номеру строки (с 1).
Исходный объект и структура дерева не меняются. Для неверного номера выбрасывается
std::out_of_range, который main обрабатывает сообщением. Стоимость поиска строки
O(m), где m — число выделенных узлов; затем копирование T. find объекта по ключу
и == идёт по одному пути: O(h), включая просмотр записей с одинаковым ключом.
