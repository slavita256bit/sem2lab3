# Стиль C/C++ лабораторных

Актуально для sem2lab3, 02.11.2026. Этот файл вместе с актуальным разделом
AGENTS.md имеет приоритет над сохранённой историей прежних решений.

## Файлы и оформление

- C++20, CMake, CLion/Linux. Заголовки в include/, реализации в src/.
  Каждый предметный класс — отдельные ClassName.h и ClassName.cpp.
  main — src/main.cpp. Новый cpp добавлять в CMakeLists.txt.
- Конструкторы и деструкторы реализовывать в заголовке, включая BinaryTree.
  Остальные методы — в cpp. Дерево и узел — один BinaryTree<T>, без вложенного класса.
- UTF-8, LF, четыре пробела, без табов и пробелов в конце строк.
  Пустые строки действительно пустые, в конце файла один перевод строки.
- Первая строка заголовка — #pragma once. Подключения подряд; после них одна
  пустая строка. В cpp сначала свой заголовок, затем нужные зависимости.
  Обязательной алфавитной сортировки include нет.
- Allman: фигурные скобки на отдельных строках. Исключение — короткие inline
  конструкторы с пустым телом. Один простой оператор if/for/while — без скобок,
  со следующей строки с отступом.
- Классы — PascalCase; методы, поля, переменные и параметры — snake_case;
  макросы — UPPER_SNAKE_CASE; enum class — именованные значения PascalCase.
- private перед public. Поля закрытые, начальные значения в объявлении;
  доступ внутри методов через this->. Методы чтения const, объекты-параметры const&.
  Тип ссылки/указателя прилегает к типу: const Vehicle&, Vehicle*, BinaryTree*&.
- Для индексов, размеров и счётчиков использовать int вместо std::size_t.
  Числовые локальные переменные перед вводом инициализировать = 0,
  символьный буфер — {}. Короткий список инициализации в строке конструктора;
  длинный на следующей строке с отступом восемь пробелов.

## Пробелы и пустые строки

- if (condition), for (...), switch (...): пробел до скобки; function(value) — без.
  Внутри круглых и квадратных скобок лишних пробелов нет.
- Вокруг бинарных операторов и присваивания один пробел; после запятой и точек
  с запятой в for один пробел. Унарные операторы, ::, ->, ., [] без пробелов.
  В обычном цикле использовать i++.
- Между определениями методов одна пустая строка. Комментарий прилегает к сигнатуре,
  сигнатура к открывающей скобке. После { и перед } пустых строк нет.
- Внутри метода одна пустая строка между этапами подготовки, ввода, обработки,
  вывода. Подсказку и ввод не разделять. Перед завершающим return после
  содержательного блока — одна пустая строка; короткому геттеру она не нужна.
- В заголовке разделять поля, вспомогательные методы, конструкторы, пары
  геттер/сеттер, ввод/вывод и операторы. Между многострочными inline-методами
  одна пустая строка. get_X и set_X держать рядом.
- case на уровне switch, тело на четыре пробела глубже. Обычно между ветвями
  пустая строка; согласованное исключение для создания транспорта:
  case 1: new_object = new DumpTruck; break;
  Все три такие ветви подряд, без дополнительных областей {}.
- Хвост do/while: while (...) на новой строке.

## Комментарии и переносы

- Короткие русские названия действий: «Получение …», «Изменение …», «Вывод …».
  В h комментарий справа от объявления, // в колонке 101 (100 символов до //).
  Для слишком длинного объявления оставить хотя бы два пробела, не разрывая код
  только ради комментария. В cpp комментарий перед методом с колонки 1.
- Новые поля и объявления методов подписывать; не комментировать каждую очевидную
  строку тела. Блок задания в начале заголовка. Тестовый ввод — блоком после main.
- Короткий std::format целиком в одной строке, в том числе с двумя аргументами.
  Длинный вызов переносить по аргументам с дополнительным отступом четыре пробела.
  Не переносить короткий вызов только из-за количества аргументов.
- Цепочки << не переносить из-за длины строки. Несколько строк подсказки —
  отдельные std::cout, без склейки соседних литералов.

## Приёмы реализации

- Предпочитать готовые средства std собственным аналогам: algorithm, format,
  char_traits и т. п. Исключения — учебные String и BinaryTree, требуемые заданием.
- String хранит char*, использует new[]/delete[]; не заменять его std::string.
  Длину получать через char_traits, копирование и поиск через algorithm.
  Собственный formatter<String> позволяет передавать String в std::format.
- Таблица через std::format, без Table, подсчёта UTF-8 вручную и символов |.
  Единицы в скобках: «Груз (т)», «Кузов (м3)», «АКБ (кВт·ч)».
  Год и места передавать числами, без to_string. Для double нужна одна цифра
  после точки; строковую точность к числу не применять. Маршрут пока использует
  старый строковый формат .7 и to_string; при переходе к числу менять их вместе.
- Не создавать interaction, demonstration, фабрики, классы приложения и обёртки.
  В main.cpp только main; меню непосредственно внутри него.
  Свои шаблоны нужны дереву, не созданию транспорта или таблице.
- Не использовать smart pointers, variant и vector для текущего хранения.
  Хранилище — три BinaryTree конкретных конечных классов, см. CONTEXT.md.
  Дерево владеет переданными через add(T*) объектами и освобождает их в clear().
- Не добавлять if(cin), if(stream), fail/eof и циклы восстановления ввода.
  Номера действий, объектов и классов проверять. Фиксированного лимита объектов нет.
  Марка вводится токеном через >>, без getline и обязательной отдельной строки.
- >> и << — friend, реализация непосредственно в операторах, без read/write.
  Базовую часть передавать через static_cast<Base&>/static_cast<const Base&>.
  Не перенаправлять вывод базового оператора обратно к наследнику.
- Виртуальные методы использовать для нужного поведения: print_read_info,
  print_header, change_field; деструктор Vehicle виртуальный. Геттеры не виртуальные.
- После явного cast при объявлении переменной предпочитать auto, чтобы не повторять
  тип. Не затенять поля локальными переменными (например, brand_text вместо brand).
- Ранний return/continue для особых случаев; не наращивать вложенность.
  В конце main return 0; локальные деревья освобождают объекты своими деструкторами.
- Не добавлять закомментированные альтернативы без необходимости; старый архив
  не чистить и не форматировать вместе с текущей задачей.

## Проверка и документы

Собирать GCC и Clang с предупреждениями, учитывать clang-tidy/CLion. Для изменений
дерева проверять поиск, дубликаты, все случаи удаления, порядок обхода и владение
памятью. Косметические правки не требуют искусственных тестов.

README не нужен. Отчёт Typst: сохранить титул и оформление прошлой лабы,
не добавлять описание реализации. Диаграмма закомментирована до отдельного рисунка
пользователя. Лабу 4 затем оформлять отдельным проектом или согласованной веткой.
